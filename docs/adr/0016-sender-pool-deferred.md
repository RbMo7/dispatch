# Sender Pool is a roadmap item, not part of the first phase

Stellar SDP's channel-account pattern (many sender accounts, each with its own sequence number, so one stuck transaction only blocks its own account) is worth adopting later as a Sender Pool (see `CONTEXT.md`) — the reason it matters here is fault isolation, not raw throughput, since the atomic nonce counter already lets nonces be assigned and broadcast concurrently without contention. It's deferred: it needs pre-funded/allocated pool wallets and per-member Signer registration, real scope on top of what single-Sender dispatch already needs. Single-Sender sequential dispatch — already fault-tolerant via `ABANDONED` status and Retry Policy (ADR-0003/0004) — ships first; Sender Pool is documented as the next scaling step, not built speculatively ahead of it.
