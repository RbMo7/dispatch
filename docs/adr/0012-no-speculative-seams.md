# No interface for a module with only one real adapter

Two places this came up: the EVM nonce counter (only EVM needs a sequential-integer nonce — Solana's model is structurally different) and the Signer client (the real variability in signing backends already lives on the other side of the network boundary, per ADR-0002 — there is currently exactly one way to "call the configured Signer URL"). In both cases, one real adapter doesn't justify a cross-cutting interface: the nonce counter stays a private implementation detail inside the EVM Chain Handler, and the Signer client is one concrete implementation with no `SignerClient` interface layered on top. An interface built from a sample size of one is a guess, not a design — add either interface only when a second, genuinely different real adapter shows up.
