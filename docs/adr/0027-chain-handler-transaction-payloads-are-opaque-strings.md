# A Chain Handler's unsigned/signed transaction payloads are opaque strings, not `unknown`

Issue 05 (`core-engine-scaffold`) specified the Chain Handler interface's `UnsignedTransaction`/`SignedTransaction` payloads as `unknown`, "matching the reference implementation's `unsignedTransaction: unknown` pattern" — nothing outside the Chain Handler that produced one should assume its shape. That held up until issue 06 (the Coordinator) needed to actually use a signed payload for two things a Chain Handler-opaque `unknown` can't support: handing it to the Signer client as `unsignedTxBytes` (already a `string`, per ADR-0002's `POST /sign` contract), and persisting it as `Transaction.signedBytes` (already a `string` column, `repository/dispatch-store.ts`). An `unknown` gives the Coordinator no legal way to produce either without an unspecified serialization step hidden somewhere — either inside `sign()` with no return value to carry the result out, or, worse, the Coordinator reaching into a value it isn't supposed to understand.

`UnsignedTransaction` and `SignedTransaction` are now typed `string` instead: an opaque, Chain-Handler-defined encoding (e.g. base64) that the engine core still never decodes or assumes anything EVM- or Solana-shaped about — opacity is about *meaning*, not the TypeScript type used to carry it. For every real chain this project targets, the exact bytes `broadcast()` sends are the same bytes worth keeping as `Transaction.signedBytes`, so there's no real serialization step being hidden by widening the type; `unknown` was stricter than the actual design needed.

## Consequences

This revises issue 05's own text after that issue was already implemented and reviewed — flagged here per this repo's own rule (AGENTS.md: "if you think [a decision]'s wrong, say so and propose a new ADR rather than silently deviating") rather than left as an undocumented reversal. `chain-handler.ts`, `stub-chain-handler.ts`, and the conformance suite were updated together so nothing straggles on the old `unknown` typing. A real Chain Handler (Solana next) still owns its own encoding entirely — this only pins that whatever it chooses must be representable as one string, which every realistic encoding already is.
